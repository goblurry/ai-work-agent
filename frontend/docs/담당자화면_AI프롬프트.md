# 팀원이 자신의 AI에 전달할 프롬프트

아래 내용을 붙여넣고 저장소의 frontend 폴더를 열어 작업하세요.

---

현재 저장소에 구현된 학생 화면을 유지하면서 학사 문의 처리 시스템의 담당자 화면을 만들어 줘. 코드를 먼저 읽고 기존 구조와 API를 재사용해 실제로 실행 가능한 React 화면을 구현해 줘.

먼저 아래 파일을 읽어 줘.
- frontend/docs/디자인_및_작업안내.md
- frontend/docs/API_명세_연결가이드.md
- frontend/docs/openapi.json
- frontend/src/student/StudentApp.jsx
- frontend/src/shared/styles.css, api.js, Icon.jsx
- frontend/vite.config.js, package.json

`frontend/staff` 브랜치에서 작업하고 담당자 코드는 frontend/src/staff에 작성해 줘. 학생 화면과 공통 API·폰트를 통째로 다시 만들지 말아 줘. 기존 담당자 초안이 있다면 필요한 기능만 새 구조에 연결해 줘.

디자인은 특정 학교 이름이나 로고 없이 범용적인 학사 행정 서비스로 만들어 줘. Pretendard, #00462a 녹색, 흰색·연회색, 얇은 구분선과 단정한 입력창을 사용해 줘. 녹색은 주요 동작에만 사용하고 과도한 카드, 큰 영문 소제목, 홍보용 히어로, 그라데이션, 이모지, AI 캐릭터, 장식용 통계는 넣지 말아 줘. 공통 CSS 변수와 학생 화면의 밀도·간격·버튼 스타일을 따라 줘. 담당자 전용 스타일은 .staff- 접두어로 분리해 줘.

담당자 화면은 다음 구조로 구현해 줘.
1. 로그인과 /auth/me의 role에 따른 학생·직원 화면 분기. 직원 API 접근은 서버도 검증하므로 client role을 요청에 넣지 마.
2. 공통 헤더와 왼쪽 메뉴: 대시보드 / 웹 문의 / 전화 문의.
3. 대시보드: 오늘 날짜와 전화 접수 버튼, 한 줄 집계, 넓은 미처리 문의 목록, 오른쪽 최근 등록 답변. 큰 숫자 카드들을 나열하지 말고 처리할 문의를 중심으로 구성해. GET /inquiries로 실제 집계하며 오늘 날짜는 Asia/Seoul 기준이야. 캘린더는 제외해.
4. 웹 문의: channel=web 목록. 답변 대기 / 학생 보완 대기 / 답변 완료 탭. waiting_student는 보완 대기, completed는 완료, 나머지는 답변 대기로 묶어. 완료한 문의는 삭제하지 말고 완료 탭으로 이동해.
5. 전화 문의: 관리자가 통화하며 입력하는 유형별 조건·문의 폼과 channel=phone 기존 목록. 저장하고 근거 확인은 POST /inquiries 후 반환된 ID로 run 호출. 저장 성공 후 run이 실패하면 같은 문의를 재실행하고 중복 등록하지 마.
6. 공통 문의 상세: GET /inquiries/{inquiry_id}. 원문·학생 조건·접수 경로를 상단에, 근거·판단과 답변 편집을 아래에 배치해. run 결과의 evidence·support_summary·warnings·missing_fields·trace를 실제 응답으로 표시해.
7. 담당자 질문이 있으면 질문·선택지를 그대로 표시하고 선택과 메모를 입력해. 현재 선택형 질문은 학수번호 문의 중심이고, 다른 문의는 판단 텍스트 입력이야.
8. compose로 학생 답변 초안을 생성해. draft_kind=evidence_summary인 근거 요약을 학생 답변으로 취급하지 마. 초안 편집·저장은 review(action: edit), 최종 등록은 review(action: complete). 완료 전 학생에게 공개하지 마.
9. 웹 문의 정보 보완은 request-info. 학생이 보완하면 received로 돌아오고 담당자가 run 재실행. 전화 문의는 통화로 확인한 조건을 run 본문에 넣어 재실행해.
10. 완료 후 목록을 갱신하고 학생 내 문의에서 final_answer가 확인되도록 해. 전화 문의는 통화 처리 기록으로 사용하며 학생 계정에 자동 연결되는 것으로 표현하지 마.

실제 업무 화면에는 API 경로나 개발 설명을 표시하지 마. 좁은 화면은 한 열로 전환하고 실행 기록은 접었다 펼칠 수 있게 해.

API는 frontend/src/shared/api.js의 request와 post를 사용하고 쿠키 인증 credentials:include를 유지해. 로컬은 npm run dev, http://127.0.0.1:5173, /api 프록시를 사용해. 서버 키나 DB 연결 문자열을 프론트에 넣지 마.

run은 동기 응답이며 실시간 단계 스트리밍은 없어. 버튼 중복 실행을 막고 로딩을 표시해. 초안 생성 실패 시 기존 입력과 초안을 보존하고 다시 시도할 수 있게 해. 완료/학생 보완 대기 등 상태에 맞춰 동작을 제한하되 서버 오류도 처리해. 자료가 없다는 사실을 불가 판정으로 바꾸지 마.

작업 후 빌드하고 실제 학생 접수→담당자 처리→학생 최종 답변 조회를 확인해 줘. 기존 학생 화면도 모바일에서 깨지지 않는지 확인해 줘. 프론트 배포 주소가 정해지면 API 가이드에 따라 프록시와 백엔드 CORS를 설정하고 설명해 줘. 커밋·푸시는 사용자가 요청할 때 해 줘.
