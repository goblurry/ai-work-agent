# 담당자 화면 개발 안내

학생 화면은 구현되어 있습니다. 담당자 화면을 같은 React 앱에 추가하고 프론트엔드 전체를 배포해 주세요. 백엔드는 이미 배포되어 있습니다.

## 작업 위치

최신 main에 학생 화면 PR을 반영한 뒤 `frontend/staff` 브랜치를 만들어 작업합니다. `frontend`라는 단일 공유 브랜치보다 화면별 브랜치로 작업하고 PR을 합치는 편이 충돌을 줄입니다.

| 경로 | 용도 |
|---|---|
| `src/student/StudentApp.jsx` | 구현된 학생 화면. 접수·조회·정보 보완 |
| `src/staff/` | 새 담당자 화면 |
| `src/shared/api.js` | 로그인 쿠키를 포함하는 공통 API 함수 |
| `src/shared/Icon.jsx` | 공통 아이콘 |
| `src/shared/styles.css` | 디자인 토큰·학생 및 공통 스타일 |
| `src/main.jsx` | 현재 학생 화면 진입점. 역할별 화면 분기를 추가할 위치 |

기존 `feat/frontend`의 담당자 초안을 참고할 수 있지만, 학생 화면의 package.json·API 함수·공통 CSS를 통째로 덮어쓰지 않습니다. 필요한 기능을 `src/staff`로 옮겨 연결하세요. 개인 작업 브랜치를 만든 후 변경합니다.

## 디자인 방향

특정 학교의 공식 서비스가 아닌 범용 학사 문의 처리 시스템입니다. 학교명·학교 로고를 넣지 않습니다. 녹색은 참고한 색상으로만 사용합니다.

- Pretendard Variable을 앱에서 직접 제공. CSS의 공통 font-family를 상속합니다.
- 주요 색상: `--green: #00462a`, 밝은 강조 배경 `--mint: #eef5f1`.
- 본문 `--ink: #1d2924`, 보조 텍스트 `--muted: #737e77`, 구분선 `--line: #e1e7e3`.
- 배경 `--canvas: #f6f8f6`, 콘텐츠 흰색. 카드 모서리 5~8px.
- 얇은 구분선, 충분한 행 간격, 좌측 정렬, 단정한 입력창. 실제 행정 업무 화면에 맞게 구성합니다.
- 페이지 제목은 28px 안팎. 긴 영문 소제목과 큰 홍보 문구를 넣지 않습니다.
- 강조 버튼은 주요 동작에만 녹색으로 사용합니다. 보조 동작은 텍스트 또는 테두리 버튼으로 구분합니다.
- 배경 그라데이션, 빛나는 효과, 과도한 둥근 카드·배지, 이모지, AI 캐릭터, 가상의 통계 카드는 넣지 않습니다.
- 학생의 질문·담당자 답변은 줄바꿈을 유지하고 긴 문장은 자동 줄바꿈합니다.
- 작은 텍스트로 정보를 빽빽하게 넣기보다 자료·판단·답변 작성 영역을 명확히 분리합니다.

공통 CSS 변수를 재사용하고 담당자 전용 CSS는 `src/staff/styles.css`에 `.staff-` 접두어로 작성합니다. 학생 화면용 클래스나 전역 태그 스타일을 변경하면 학생 화면도 함께 확인하세요.

## MVP 화면 구성

공통 헤더와 왼쪽 메뉴에 대시보드 / 웹 문의 / 전화 문의를 둡니다. 로그인 후 `/auth/me`의 role로 student/staff 화면을 구분합니다. 역할을 임의로 선택하지 않습니다.

### 대시보드

숫자 카드를 크게 나열하지 않고 **처리할 문의를 중심으로** 구성합니다.

- 상단: 작은 페이지 제목, 오늘 날짜, 오른쪽 `전화 문의 접수` 버튼.
- 요약 한 줄: 미처리 / 학생 보완 대기 / 오늘 답변 완료 / 오늘 접수 건수.
- 주 영역: 답변을 기다리는 문의. 웹·전화 구분, 문의 유형, 접수 시간, 질문 요약, 학과·입학연도. 오래된 접수부터 표시합니다.
- 오른쪽 보조 영역: 최근 등록한 답변. 완료 시각·문의 요약·최종 답변을 간결하게 표시합니다.
- 좁은 화면은 한 열로 전환합니다. 학사일정 캘린더는 이번 MVP 범위에 포함하지 않습니다.

`GET /inquiries`로 목록을 받아 집계합니다. 오늘 접수는 created_at, 오늘 완료는 completed_at을 Asia/Seoul 날짜 기준으로 비교합니다. 미처리는 completed와 waiting_student를 제외한 전체 문의입니다. 통계 전용 API나 임의의 통계를 만들지 않습니다.

### 웹 문의

`GET /inquiries` 결과 중 channel=web을 표시합니다. 상태별 탭은 다음과 같습니다.

- 답변 대기: completed, waiting_student를 제외한 상태.
- 학생 보완 대기: waiting_student.
- 답변 완료: completed.

행에는 접수일·유형·질문 요약·상태를 표시하고, 클릭하면 `GET /inquiries/{inquiry_id}`로 공통 상세 화면을 엽니다. 완료한 문의는 삭제하지 않고 완료 탭으로 이동합니다.

### 전화 문의

관리자가 통화 중 문의 유형, 학생 조건, 질문 내용을 입력합니다. 유형에 따라 조건 입력란을 표시하며 학생 접수 폼의 데이터 모델을 재사용합니다. 기존 전화 문의 목록은 channel=phone으로 구분합니다.

`저장하고 근거 확인`은 먼저 `POST /inquiries`로 channel=phone 문의를 저장하고, 반환된 inquiry_id로 run을 호출합니다. 저장 후 실행이 실패하면 같은 ID로 재시도하며 문의를 중복 접수하지 않습니다. 음성 녹음·자동 전사는 범위에서 제외합니다.

### 공통 문의 처리 화면

상단에는 원문·학생 조건·접수 경로·처리 상태를 표시합니다. 그 아래 근거·담당자 판단 영역과 답변 초안 영역을 배치합니다.

학생 문의 확인 → 근거 확인 → 담당자 판단·메모 → 초안 생성 → 초안 수정·검토 → 승인·등록 순서입니다. 실행 기록은 접어 두고 펼쳐 볼 수 있게 합니다. 완료 문의는 final_answer와 completed_at을 표시하며 현재 MVP에서 재수정하지 않습니다.

운영 화면에는 API 경로나 구현 설명을 넣지 않습니다. API 연결 위치는 별도 연결 가이드를 참고합니다.

## 문의 처리 동작

- `Agent 실행`: run API. 완료까지 로딩·중복 실행 방지. 실제 실행 중인 단계는 API가 반환된 후 trace로 보여 줍니다. 가짜 실시간 실행 단계를 만들지 않습니다.
- `담당자 판단`: 선택형 질문이 있으면 예/아니요/추가 확인 필요 + 메모. 없으면 판단 텍스트 입력.
- `답변 초안 작성`: compose API. 근거 요약과 학생에게 보낼 답변을 구분합니다.
- `초안 저장`: review의 edit. LLM을 호출하지 않고 수정 내용을 저장합니다.
- `답변 등록`: review의 complete. 담당자 검토 후에만 완료 처리합니다.
- `다시 작성`: 판단·메모를 바꿔 compose 재호출. 사용자가 편집한 초안을 덮어쓰기 전 안내합니다.
- `정보 보완`: 웹 문의면 요청 문구·입력 항목을 확인하고 request-info. 학생이 보완하면 received로 돌아오며 담당자가 run 재실행. 전화 문의는 통화 중 확인한 조건을 run 본문에 넣어 바로 재실행할 수 있습니다.

선택형 질문은 현재 학수번호 문의 중심입니다. 모든 문의에 임의의 예/아니요 질문을 생성하지 않습니다. 검색되지 않은 내용은 불가 판정으로 바꾸지 않고 담당자 확인 사항으로 표시합니다.

## 완료 기준

학생 접수 → 담당자 목록 조회 → run → 판단/메모 → compose → 초안 수정 → complete → 같은 학생의 내 문의에서 최종 답변 확인. 전화 문의 등록과 정보 보완 후 재실행도 확인합니다.

실제 DB를 사용하므로 시연 문의임을 내용에 표시합니다. 검증용 자료를 대량 생성하지 않습니다. 시연 계정 비밀번호는 담당자에게 별도로 전달하며 Git 문서에 적지 않습니다.

배포는 담당자 화면 완성 후 프론트 전체를 한 번에 진행합니다. 학생 화면은 현재 로컬 Vite에서 실행하며 백엔드는 Hugging Face, 업무 DB는 Supabase입니다.
