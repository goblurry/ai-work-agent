## 0. 조사 범위와 방법

본 과제는 "학칙·학사안내·FAQ·공지·교육과정을 검색해 학생 문의에 근거와 함께 답하는 에이전트"다.
이 문제를 네 갈래로 분해해 각각의 선행연구를 조사했다.

| 갈래 | 질문 | 절 |
|---|---|---|
| A | 대학 학사 도메인 RAG 챗봇은 이미 어디까지 왔나 | §1 |
| B | 규정의 "언제부터 누구에게" 를 검색이 다룰 수 있나 | §2 |
| C | 검색 방식(하이브리드·메타데이터)은 무엇이 정설인가 | §3 |
| D | 이런 시스템을 무엇으로 평가하나 | §4 |

## 1. 갈래 A — 대학 학사 상담 RAG 챗봇

### A-1. hoBIT / proFILL (고려대, 2026.08) ★ 최우선 검토 대상

> Kim, Lee, Kim, Kang. *hoBIT: A Profile-Aware Retrieval-Augmented Chatbot for University Academic Advising.* arXiv:2608.26604 (전문 확인)

**우리 과제와 사실상 같은 문제를 푼다.** 초록 첫 문장:

> 대학 학사 상담에서는 동일한 질문이라도 학생의 **학과, 입학 코호트, 학위과정**에 따라 다른 답이 필요하며,
> 프로필을 모르는 검색기는 그럴듯하지만 적용되지 않는 근거를 내놓는다.

- **문제의식**: 학사 질문은 *profile-dependent*. 질의만으로 정답이 결정되지 않음
- **방법**: 오프라인 단계에서 각 청크에 "이 문서가 유효한 프로필 값"과 "해석에 필요한 프로필 필드"를 주석으로 붙여 **profile-indexed corpus** 구축. 온라인에서는 로그인·전체 프로필 요구 없이, 질의 의도와 1차 검색 결과를 보고 **필요한 필드만 역질문**(on-demand adaptive profiling)
- **대상**: 고려대 정보대학 3개 학과(CS/DS/AI), 학과·코호트·전공트랙(심화/복수/융합)별로 요건이 갈리는 상황
- **스택**: BGE-M3 임베딩 + RRF(Reciprocal Rank Fusion) 하이브리드
- **검증**: RAG 베이스라인 대비 우수 + 인간 선호도 조사. 오픈웨이트 모델로도 온프레미스 운용 가능
- **명시된 한계 (원문 Limitations 전문)**:
  1. 코퍼스·벤치마크가 **단일 단과대(정보대학)** 에 한정. 프로필 스키마는 기관마다 재설계 필요
  2. **프로필을 학생 자기보고에 의존**하며 기관 차원의 검증이 없음 → 입학연도를 잘못 입력하면 그대로 검색 결과에 전파
- **윤리 섹션**: 보조 도구이며 권위 있는 출처가 아님을 명시, 모든 답변에 출처 인용, 구속력 있는 판단은 공식 규정에 따름

**→ 팀에 주는 함의 (중요)**

1. 한준님이 LLM 추천으로 받은 스택(**BGE-M3 + 하이브리드**)은 **이 논문이 쓴 것과 동일**하다. "처음 보는 것들"이 아니라 이 도메인의 현재 표준에 가깝다. 스택 논쟁은 여기서 종료해도 된다
2. 반대로 **"입학연도별로 답이 달라진다"는 차별점은 이미 선점됐다.** 이걸 그대로 메인으로 내세우면 재현 과제가 된다
3. 다만 이 논문이 **비워둔 자리가 명확하다** → §5

### A-2. 국내 유사 연구 (초록 수준 확인)

- **RAG 기반 지능형 대학정보 질의응답 시스템** (Journal of IoT and Convergence, 2025) — 학사정보·교직원 규정 문서를 벡터DB로 색인한 QA 시스템
- **SLLM을 활용한 RAG 기반 교육기관 문서 질의응답** (KCI) — **섹션 기반 문서 파싱**과 **복잡한 표 데이터 처리**를 제안. 우리 교육과정 표 처리에 직접 참고 가치 있음 → **전문 확보 필요**
- **RAG 기반 LLM을 이용한 대학 LMS 학생 질의응답 챗봇** (KCI)
- **Development of QA System with Education-specific RAG** (문화기술융합학회, 2025)

### A-3. 해외 사례 (스니펫 수준)

- Springer, *A Review of RAG-Based LLM Chatbots for Enhanced Academic and Administrative Support in Universities* — 이 분야 리뷰 논문. **서론 인용용으로 전문 확보 권장**
- UPN Veteran Yogyakarta (LLaMA 3.1 기반), 그 외 인도네시아권 사례 다수
- 공통 성능 보고: Faithfulness 0.91, 범위 밖 질문 거부율 81.25%

**→ A-3군의 공통 한계**: 대부분 "PDF 넣고 답하기" 수준이며, 적용 시점·대상 학번 구분이 없다. 우리가 넘어야 할 기준선은 A-3이 아니라 **A-1**이다.

## 2. 갈래 B — 시간·버전 인지 검색 (우리 차별화의 핵심)

현선님 정리본 2장의 **연도 3축 분리**(① 입학연도 ② 개정일·시행일 ③ 대상 학기)는
법률 RAG 쪽에서 **temporal misgrounding** 이라는 이름으로 활발히 연구되는 주제와 정확히 같은 문제다.

| 연구 | 핵심 |
|---|---|
| *Temporal Misgrounding in Legal RAG* (프랑스 세법 버전코퍼스 벤치마크, arXiv:2608.09393) | 법적 정답은 **날짜 조건부의 이진 판정**. "비슷하게 맞는" 버전은 그냥 오답 |
| *TimelyRAG* (arXiv:2609.11572) | 의미 유사도 + **조문 단위 시간 적합성**을 결합. 질의에서 as-of 날짜를 뽑아 유효기간으로 코퍼스를 하드 필터링 |
| *VersionRAG* (arXiv:2510.08109) | 문서 버전 추적을 검색에 내장. 한계로 대규모 버전 이력 확장성·버전 입도 결정 문제를 인정 |
| *Asking For An Old Friend* (arXiv:2605.23497), *When Do LLMs Apply the Wrong Law?* (arXiv:2608.14610) | 법령 QA에서 LLM의 시간 관련 실패 유형 진단 |
| *Ontology-Driven Graph RAG for Legal Norms* (arXiv:2505.00039) | 규범을 그래프로 구조화 |

**인용할 만한 숫자** (출처: arXiv:2608.09393 스니펫, **전문으로 재확인 필요**):

> 11개 모델에서 파라메트릭 지식 strict accuracy 평균 3.0%, 현행본 정적 코퍼스 RAG 2.7%.
> **정적 RAG가 날짜상 적용되는 버전을 검색한 비율은 0%.**

→ 발표 도입부의 motivation으로 매우 강력하다. "그냥 넣고 돌리면 되지 않나"에 대한 정량적 반박이 된다.

**단, 이 연구들은 전부 법률·세법 도메인이다. 대학 학사 규정에 적용한 사례는 조사 범위에서 발견하지 못했다.**

## 3. 갈래 C — 검색 방식

- *A Hybrid Approach to Information Retrieval and Answer Generation for Regulatory Texts* (arXiv:2502.16767): 파인튜닝 sentence transformer + BM25 하이브리드가 단독 방식 대비 Recall@10, MAP@10 유의하게 상회. 규정 텍스트는 전문용어·유의어·환언 때문에 어휘 검색만으로도 의미 검색만으로도 부족
- 메타데이터 필터링이 아키텍처 개선보다 검색 정확도 기여가 크다는 보고 (업계 벤치마크, 33%→55%; **1차 출처 확인 필요**)
- RRF (Cormack et al., SIGIR 2009) — hoBIT이 채택한 융합 방식. 고전이고 구현이 단순
- BGE-M3 (Chen et al., arXiv:2402.03216) — 다국어·다기능(dense/sparse/multi-vector) 임베딩

**→ 현선님 정리본 4장의 "정확한 교과목명·규정명은 키워드 검색 병행" 판단은 문헌과 일치한다.** Qdrant 하이브리드 선택도 근거가 생겼다.

## 4. 갈래 D — 평가 방법론

- **RAGAS** (arXiv:2309.15217): Faithfulness / Answer Relevancy / Context Precision / Context Recall. 참조 정답 없이도 상당 부분 측정 가능
- hoBIT은 DeepEval 사용 + **인간 선호도 조사** 병행

**→ 우리 과제에 필요한 추가 지표**: 위 4개는 "답을 했을 때 얼마나 잘했나"만 본다.
우리 시연 시나리오 ③(규정 적용이 불명확해 담당자에게 이관)을 평가하려면 **적절히 답을 거부·이관했는가**를 재는 지표가 따로 필요하다.
A-3군 사례의 "범위 밖 질문 거부율 81.25%" 가 참고 선례.

## 5. Research Gap — 우리가 비울 자리

조사 결과를 교차하면 **비어 있는 칸이 또렷하다.**

|  | 프로필 축<br>(학과·입학연도·전공유형) | 시간 축<br>(개정일·시행일·대상학기) | 도메인 |
|---|---|---|---|
| hoBIT / proFILL | **O** | X | 대학 학사 |
| TimelyRAG, VersionRAG, 법률 RAG | X | **O** | 법률·세법 |
| 국내외 일반 대학 챗봇 | X | X | 대학 학사 |
| **학사나침반 (제안)** | **O** | **O** | **대학 학사** |

### Gap 1. 프로필 축 × 시간 축의 교집합이 비어 있다
hoBIT은 "2024학번 AI 심화트랙에게 무엇이 적용되는가"는 풀지만,
**"그 규정이 2023년에 개정됐고 기존 입학생에게는 경과조치가 있다"** 는 다루지 않는다.
법률 RAG는 반대로 시간 축만 다루고 사용자 프로필 조건은 없다.
현선님 정리본은 처음부터 **3축을 분리**하고 **예외·경과조치 필드**까지 설계해 두었다 — 이게 우리 과제의 1순위 기여다.

### Gap 2. hoBIT이 스스로 인정한 "자기보고 프로필 미검증"
> proFILL은 기관 검증 없는 자기보고 프로필에 의존하므로, 잘못된 입력(예: 부정확한 입학연도)이 검색 결과로 전파된다.

현선님 정리본 4장의 **"일반 DB: 가상 학생 정보, 수강·이수 기록"** 설계가 정확히 이 한계를 메운다.
학적 DB 조회로 프로필을 **검증**하고, 학점 합계·마감 여부는 벡터 검색이 아니라 **구조화된 값으로 계산**한다.
→ "벡터 유사도가 높다는 이유만으로 졸업 가능 여부를 확정하지 않는다"

### Gap 3. 사용자가 학생이 아니라 **담당자**다
선행 사례는 전부 학생 직접 응대형이다.
우리는 과제 요건상 **업무용**이어야 하고, 정리본 6장도 담당자 판단자료 생성·이관을 전제한다.
→ 완전자동 응답이 아니라 **근거가 갖춰지면 초안 작성 / 불명확하면 이관**이라는 설계는 선행연구와 구분되는 포지션이며,
   고위험 행정 도메인에서 더 방어 가능한 주장이다.

## 6. 제안 — 발표 서사와 다음 작업

### 서사 (3단)
1. **문제**: 학사 문의의 정답은 질문만으로 결정되지 않는다 (hoBIT) + 규정은 시점마다 다르다 (법률 RAG, 정적 RAG 적용버전 검색률 0%)
2. **선행의 한계**: 둘을 동시에 다룬 연구가 없고, 프로필은 검증되지 않으며, 전부 학생 직접 응대형이다
3. **우리**: 3축 메타데이터 + 학적 DB 검증 + 담당자 이관 설계

### 바로 할 작업
- [ ] hoBIT 원문 정독 후 proFILL 프로필 스키마 ↔ 현선님 메타데이터 표 대조 (겹침/차이 정리)
- [ ] arXiv:2608.09393 전문 확보 → "0%" 수치 1차 출처 확인 후 인용 확정
- [ ] SLLM 논문(KCI) 전문 확보 → 교육과정 **표 파싱** 방법 차용 검토
- [ ] Springer 리뷰 전문 확보 → 서론 레퍼런스
- [ ] 평가셋 설계: 3축이 실제로 갈리는 질문 위주 (예: "2020학번이 2026년에 복수전공 신청")

### 미해결 질문
- 이대 **구버전 규정**이 공개되어 있는가? 없으면 Gap 1의 시간 축 중 "개정일·시행일"은 부칙·경과조치 조문만으로 제한적으로 다뤄야 한다 (정리본 1장 A도 "구버전 공개 여부 추가 확인" 으로 남겨둠)
- 23GB 원본에 위 메타데이터를 붙일 수 있는 구조 정보(게시일, 조문 번호, 첨부 관계)가 보존되어 있는가?
