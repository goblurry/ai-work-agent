# 시스템 뼈대 — 선행연구에서 가져온 구조

- 작성일: 2026-10-02 / 작성: 신기훈
- 목적: 셋이 **바이브코딩으로 각자 만들어도 맞물리도록** 인터페이스를 먼저 고정한다.
- 원칙: **설계 결정마다 출처를 적는다.** 새로 발명한 건 ★로 표시.

---

## 0. 왜 뼈대부터인가

셋 다 AI로 코딩할 예정이다. 그러면 **각자 만든 게 안 맞물리는 게 가장 큰 리스크**다.
한준님이 만든 데이터 형식과 현선님이 만든 검색 함수가 다른 걸 기대하면, 합치는 데 며칠 날아간다.

**그래서 코드보다 먼저 고정할 것은 세 가지다.**
1. 데이터가 어떻게 생겼는가 (`schemas/`)
2. 함수가 뭘 받고 뭘 돌려주는가 (`backend/app/**/*.py` 의 시그니처)
3. 화면이 서버에 뭘 요청하는가 (`api/routes.py`)

이게 정해지면 **각자 알아서 채워도 합쳐진다.** 이 문서가 그 틀이다.

## 1. 전체 구조

```
repo/
├── docs/              # 조사·설계 (기훈)
├── schemas/           # ★ 데이터 계약 — 여기가 뼈대의 핵심
│   ├── chunk_metadata.json    문서 청크가 어떻게 생겼는가
│   ├── student_profile.json   학생 정보가 어떻게 생겼는가
│   └── answer_result.json     응답이 어떻게 생겼는가
├── eval/
│   └── questions.jsonl        시험문제 32개
├── backend/app/
│   ├── ingest/       parse.py      문서 → 청크        (한준)
│   │                 annotate.py   메타데이터 주석     (한준+현선)
│   ├── retrieval/    search.py     3축 하이브리드 검색 (현선)
│   ├── agent/        verify.py     ★ 적용 조건 검증    (현선)
│   │                 loop.py       에이전트 루프       (현선+한준)
│   └── api/          routes.py     FastAPI 계약
└── frontend/         React
```

## 2. 설계 결정과 출처

| # | 결정 | 출처 | 비고 |
|---|---|---|---|
| D1 | 청크마다 **적용 대상을 주석**하고, 무관한 필드는 **null** | hoBIT §2.1 | 그대로 차용 |
| D2 | **static / dynamic 인덱스 분리** (규정 vs 공지) | hoBIT §2.1 | 그대로 차용 |
| D3 | **의도 분류** 후 retrieval 질의만 검색으로 | hoBIT §2.2.1 | 그대로 차용 |
| D4 | **BGE-M3 + 하이브리드 + RRF** | hoBIT / arXiv:2502.16767 / SIGIR'09 | 그대로 차용 |
| D5 | 섹션 기반 파싱 + **표 구조 보존** | SLLM 논문 (KCI) | 전문 확보 후 상세 적용 |
| D6 | 검색 품질이 낮으면 **질의 조정 후 재검색** | CRAG / Self-RAG | 구조 차용 |
| D7 | **시간 축 3분리** (게시일/시행일/대상학기) + 경과조치 | ★ 없음 (법률 RAG에서 착상) | **우리 기여 C1** |
| D8 | as-of 기준 **하드 필터링** | TimelyRAG | 아이디어 차용 |
| D9 | 프로필을 **학적 DB 조회로 검증** | ★ 없음 (hoBIT이 한계로 명시) | **우리 기여 C2** |
| D10 | 학점·마감은 **구조화 계산**, 벡터 아님 | ★ 없음 | **우리 기여 C2** |
| D11 | 루프 종료 조건 = **"적용 조건 검증 통과"** | ★ 없음 (CRAG는 검색 점수) | **우리 기여** |
| D12 | 응답 **3분기** + 확정불가 사유 유형 | ★ 분기는 정리본 §6 / 유형화는 arXiv:2605.14830 | **우리 기여 C3** |
| D13 | 자료 충돌 시 **자동 선택 금지, 양쪽 제시** | ★ 정리본 §2 | **우리 기여** |
| D14 | **실행 기록(trace)을 화면에 노출** | SpheriCity(arXiv:2606.13854) + 정리본 §6 | 차용 |
| D15 | 결정권은 항상 **직원**에게 (AI2L) | HITL 리뷰 / CARE | 차용 |

> **★이 7개.** 발표에서 "우리가 한 것"은 이 7개다. 나머지 8개는 선행연구에서 가져온 것이고, 그걸 **밝히는 게 오히려 신뢰를 준다.**

## 3. 역할 분담 제안 (겹치지 않게)

| 사람 | 폴더 | 브랜치 | 산출물 |
|---|---|---|---|
| **한준** | `backend/app/ingest/` | `feat/ingest` | 23GB → 청크 + 메타데이터 |
| **현선** | `backend/app/retrieval/`, `agent/`, `api/`, `frontend/` | `feat/retrieval`, `feat/api`, `feat/ui` | 검색·검증·화면 |
| **기훈** | `docs/`, `eval/`, `schemas/` | `docs/*`, `feat/eval` | 조사·평가·데이터 계약 |

**폴더가 겹치지 않으므로 merge 충돌이 거의 없다.** Category G는 merge log가 평가 대상이니, 각자 자기 브랜치에서 작업하고 PR로 합친다.
