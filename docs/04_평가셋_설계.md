# 평가셋 설계 — 학사나침반 Eval Set v0

- 작성일: 2026-10-02 / 작성: 신기훈
- 상태: **설계 + 시드 질문 32건**. 정답 근거(gold evidence)는 데이터 수집 후 채운다.

---

## 0. 왜 평가셋을 먼저 만드는가

지금 팀에는 답이 안 난 질문이 몇 개 있다.

- 23GB 원본이 **쓸 만한가** / 정제가 얼마나 필요한가
- 청킹 단위를 조문으로 할까 항목으로 할까
- 하이브리드 검색이 실제로 **이득인가**
- 메타데이터를 어디까지 붙여야 하는가

이건 토론으로 안 끝난다. **평가셋이 있으면 전부 숫자로 결정된다.**
그리고 평가셋은 **원본 데이터 없이 지금 만들 수 있다.**

> 핵심: 평가셋은 "나중에 성능 재는 도구"가 아니라 **지금 설계 논쟁을 끝내는 도구**다.

## 1. 설계 원칙

### 1-1. 일반 질문은 넣지 않는다
"졸업학점이 몇 학점인가요?" 같은 질문은 아무 RAG나 맞힌다. 변별력이 없다.
**우리 평가셋은 3축이 실제로 갈리는 지점만 모은다.**

### 1-2. 테스트 축 라벨
| 코드 | 축 | 무엇을 보는가 |
|---|---|---|
| **P** | 프로필 | 학과·입학연도·전공유형에 따라 답이 갈리는가 |
| **T** | 시행일·개정 | 규정 개정 전/후, 경과조치, 기존 입학생 적용 여부 |
| **S** | 대상 학기 | 어느 학기의 신청 기간·절차인가 |
| **C** | 계산 | 학점 합계·충족 여부 등 구조화 계산이 필요한가 |
| **X** | 함정 | 근거가 없거나 자료가 충돌 → **답하면 안 되는** 질문 |

**P×T 복합 문항이 우리 과제의 핵심 변별 구간이다.** (hoBIT은 P만, 법률 RAG는 T만)

### 1-3. 기대 동작 라벨 (정리본 §6 시연 3종과 일치)
| 코드 | 기대 동작 |
|---|---|
| **A** | 근거 충분 → 출처 달아 답변 |
| **B** | 정보 부족 → 필요한 필드만 역질문 후 답변 |
| **C** | 근거 불충분·충돌 → **담당자 이관 + 판단자료** |

X 유형이 A로 나오면 **환각**, 답할 수 있는 A 문항이 C로 나오면 **과잉 이관**이다. 둘 다 감점.

### 1-4. 페어 설계
가능하면 **같은 질문, 다른 조건**으로 쌍을 만든다. 이게 가장 강력하다.
예: Q07/Q08은 질문이 글자 단위로 같고 학번만 다르다. 시스템이 둘 다 같은 답을 내면 **프로필 축이 작동하지 않는 것**이 즉시 드러난다.

## 3. 지표

### 3-1. 검색 단계
| 지표 | 정의 | 목표 |
|---|---|---|
| **적용근거 정확도 (strict)** | 학번·날짜상 **실제 적용되는** 근거를 Top-k에 넣었는가 | 주 지표 |
| 느슨한 정확도 | 주제가 맞는 근거를 넣었는가 | 비교용 |
| Context Precision / Recall | RAGAS | 보조 |

> **strict와 느슨한 정확도의 격차**가 곧 "시간·프로필 축이 필요하다"는 증거다.
> 법률 RAG 문헌(arXiv:2608.09393)이 보고한 격차를 우리 도메인에서 재현하면, 그 자체가 발표의 핵심 슬라이드가 된다.

### 3-2. 생성 단계
| 지표 | 정의 |
|---|---|
| Faithfulness | 답변 주장이 근거로 뒷받침되는가 (RAGAS) |
| 출처 정확도 | 인용한 조문·URL이 실제로 그 내용을 담고 있는가 |

### 3-3. 분기 판단 (우리만의 지표)
| 지표 | 정의 |
|---|---|
| **적절 이관율** | X 문항(Q29~32)을 C로 처리한 비율. **높을수록 좋음** |
| **환각율** | X 문항을 A로 답해버린 비율. **0 목표** |
| **과잉 이관율** | A 기대 문항을 C로 넘긴 비율. 낮을수록 좋음 |
| 평균 역질문 수 | B 문항에서 몇 번 물었는가. 적을수록 사용자 부담 ↓ |

## 4. 베이스라인 비교 (발표용 Ablation)

같은 32문항을 네 조건에서 돌린다.

| 조건 | 구성 | 보여주는 것 |
|---|---|---|
| ① LLM 단독 | 검색 없음 | 파라메트릭 지식의 한계 |
| ② Naive RAG | 벡터 검색만, 메타데이터 없음 | 일반 RAG 수준 |
| ③ + 하이브리드 | 벡터+키워드 | 검색 방식의 기여 |
| ④ **+ 3축 메타데이터** | 전체 | **우리 기여분** |

③→④의 strict 정확도 상승폭이 **우리가 주장할 수 있는 숫자 전부**다.
이 표 하나가 발표의 결론 슬라이드가 된다.
